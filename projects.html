法律领域本地化 RAG 智能问答系统

独立开发 · 从需求分析到部署上线全流程

项目背景

法律条文检索对准确性要求极高，而通用 RAG 方案处理法条时有两个突出问题： 一是常规分块策略会把条文从「编—章—节—条」的层级结构中切断， 检索回来的片段语义破碎；二是用户的口语化表述与法条的专业语言之间存在语义鸿沟， 直接检索召回率很低。

我的工作

  • 大模型选型与接入：选定 Qwen3-8B 本地部署 + BGE-M3 embedding 方案，完成推理环境搭建与生成参数调优。
  • Prompt 策略设计：设计法律条文专用结构化分块器（按编／章／节／条层级切分并注入上下文标头），根治「条文被切断」导致的检索语义破碎问题；设计术语规范化与查询改写 Prompt，解决口语表述与法条语言脱节的问题。
  • 知识库构建与检索优化：实现多查询扩展 + HyDE 分离式检索，结合 BM25 与向量的双路混合检索及 RRF 融合排序提升召回精度；引入知识图谱增强罪名关联，覆盖法条之间的隐含引用关系。
  • 自我反思机制：实现生成后自我反思校验，核验引用条文的真实性，抑制大模型幻觉。
  • 服务化与工程落地：基于 FastAPI 构建异步接口层，完成知识库管理、质量评估服务与单元测试，系统可稳定对外提供问答服务。

成果

系统可稳定对外提供问答服务。结构化分块 + 混合检索 + 自我反思校验三层机制叠加后， 回答的条文引用准确率与忠实度显著提升，有效抑制了法条编造问题。

基于物理先验驱动的海洋云平台智能威胁检测

核心研发 · SCI 二区论文 + 发明专利

项目背景

海洋科学云平台的安全痛点很特殊：拥有合法凭证的用户可以利用海洋物理规律实施推理攻击， 而传统访问控制机制对这类攻击在语义上完全不可见——权限检查通过，攻击却已经发生。

我的工作

  • 威胁模型构建：参与构建涵盖 6 类攻击、L1–L4 四级数据密级、三维核心接口的威胁模型。
  • 提出检测框架：提出基于「对偶原理」的物理先验检测框架——海洋物理约束既是攻击者的推理通道，也是防御者的检测信号来源。
  • 特征工程：设计四组特征提取器，量化数据访问、时序行为、资源使用、I/O 不对称四类物理行为信号，构建 128 维非均匀分配的行为特征表示，将多源异构日志转化为可学习的物理语义特征空间。
  • 模型研发：研发 GFAG-Transformer 检测模型，通过分组特征注意力门控（GFAG）将「攻击类型→信号维度」的先验映射注入组间注意力权重；采用 KL 散度正则 + 余弦退火实现物理先验的渐进式内化；基于攻击者画像先验动态调制三级决策阈值，实现「放行—审计—阻断」的差异化风险治理。
  • 实验验证：在真实生产日志标注数据集（含 33% 真实攻击事件）上完成模型训练与系统评估，采用 10 随机种子与统计显著性检验；通过消融实验验证 GFAG 结构、先验正则、自适应阈值三者的独立贡献。

成果

0.93Macro-F1
0.98高风险召回率
0.02低风险误报率
+13pp较最强基线

三层决策准确率 0.87，Macro-F1 达 0.93，较最强基线 LogFormer 提升约 13 个百分点。 可解释性验证显示：先验正则退火归零后，模型注意力分布仍稳定对齐理论先验目标 （关键类别 KL 散度 0.012），证明性能增益源于物理先验的有效内化， 而非模型容量的堆叠。

基于深度学习的海洋温度智能预测平台

项目负责人 · 第四届全国智慧海洋大数据与人工智能应用创新大赛（2025）获奖项目

项目背景

海洋温度序列具有非平稳、多尺度周期耦合的特点，直接套用通用时序模型会出现 预测精度低、实时性差的问题。

我的工作

  • 模型设计：设计差分变换（DIFF）+ STL 时序分解 + LSTM 的复合预测模型（DIFF-STL-LSTM），将序列分解为趋势／季节／残差分量，分通道独立建模后加权融合；进一步构建 DIFF-STL-ConvLSTM 实现区域海温的时空联合建模，突破单点预测局限。
  • 数据工程：汇聚卫星遥感、海洋浮标、观测站点等多源异构数据约 5200 万条，完成时空对齐、质量控制（3σ 准则／孤立森林异常检测）、特征工程与归一化，构建南海区域海表温度时空数据集。
  • 训练与评估：主导模型训练与评估全流程，通过消融实验验证各模块的有效性。
  • 平台搭建：搭建前后端分离微服务平台（Django + React + Redis + Docker），集成数据管理、模型训练、预测服务与可视化模块。
  • 项目管理：作为项目负责人统筹团队分工与进度，负责数据链路搭建、预处理与预测模型评估。

成果

98.8%预测准确率
0.388RMSE（°C）
5200万多源数据条数

较基础 LSTM，RMSE 由 0.414 降至 0.388°C，预测准确率提升至 98.8%（提升约 20%）； 区域预测模型 MAE 0.4203，准确率 98.35%。 成果已在海洋牧场数字化管理平台与三维地球可视化系统集成部署运行， 并以软件著作权「海洋表面温度预测系统」固化。

海水养殖实时监测预警与智能管理系统

项目负责人 · 第三届全国智慧海洋大数据与人工智能应用创新大赛（2024）获奖项目

项目背景

海水养殖长期存在人工经验依赖、异常发现滞后、资源粗放投喂等痛点， 养殖户往往在鱼群出现明显异常后才发现问题，损失已经造成。

我的工作

  • 系统设计：设计「多源感知—数据融合—智能预测—预警决策」一体化系统，接入水质传感器、水下摄像头、声呐、气象站、浮标与卫星遥感等多源设备数据，经清洗质控与标准化后统一入库，实现养殖环境全方位实时感知。
  • 预测模型：构建 LSTM-BP 组合水质预测模型（Keras／TensorFlow），针对单一 LSTM 收敛慢、精度不足的问题，将 LSTM 隐层输出接入 BP 网络做二次误差修正，通过反向传播联合优化权重偏置，实现水温、pH、溶解氧等多参数未来一周滚动预测与超限自动预警。
  • 视觉检测：集成基于计算机视觉的鱼类行为目标检测（OpenCV 视频流处理 + 深度学习检测模型），识别鱼类进食、活动及异常死亡事件。
  • 健康评估：结合随机森林／SVM 健康评估模型输出鱼类健康风险报告。
  • 工程实现：采用 Django + MySQL + WebSocket 架构实现监测数据实时推送与可视化看板（7 类统计视图）。

成果

已在大连海洋大学水产养殖学实验教学示范中心完成整套软硬件部署， 并在海洋养殖环境信息综合应用服务平台验证运行， 实现了从环境感知到预警决策的闭环。

LSTM-BP OpenCV 随机森林 SVM Django MySQL WebSocket

Spark Streaming 电商实时数仓与数据可视化平台

核心开发 · 实时流计算与可视化大屏

项目背景

电商业务需要对用户行为与交易数据进行实时指标计算， 让运营侧能在分钟级看到转化、留存等关键指标，而不是等 T+1 的离线报表。

我的工作

  • 流计算开发：负责核心流计算开发，完成 ODS 到 DWS 层的实时分流、维度合并与多流关联，编写 Spark 任务与复杂统计分析 SQL，并针对热点查询做性能优化。
  • 跨批次延迟治理：基于 Redis 缓存状态解决双流 Join 的跨批次延迟问题，保障实时维度关联的完整性。
  • 一致性保障：手动维护 Kafka Offset 配合 Elasticsearch 幂等写入，实现端到端精准一次消费语义（Exactly-Once），杜绝重复计数。
  • 数据服务：用 Spring Boot 开发数据 API 供可视化大屏调用，参与指标口径梳理，理解「业务指标 → 可复用报表」的沉淀过程。

成果

实现端到端 Exactly-Once 消费语义，杜绝了实时指标的重复计数问题； 沉淀出一批口径统一、可供业务侧自助取数的报表页面。

基于 OBE 理念的过程考核与达成度分析系统

独立开发 · 本科毕业设计 · 软件著作权 2025SR0343232

项目背景

高校课程的过程性考核长期依赖手工记录与 Excel 统计。教师需要在学期末把随堂测试、 阶段测试、实践考核等多个环节的成绩按权重折算成课程目标达成度，工作量大且容易算错； 同时缺少工具支撑 OBE（成果导向教育）所要求的「课程目标—知识点—试题」三级映射与量化分析。

我的工作

  • 服务端整体设计与开发：基于 Spring Boot 搭建 Controller-Service-Mapper 分层架构，使用 MyBatis Plus 完成 ORM 映射与数据访问，实现课程指标设置、题库组卷（单选／多选／判断／填空／主观题）、阶段测试／实践考核／随堂测试三种考核方式的全流程。
  • 课程达成度加权计算引擎：试题关联知识点、知识点映射课程目标，按各考核环节权重分层加权计算目标达成度，并生成可视化柱状图。例如目标 2 的达成度为 (100×12% + 90×12% + 100×14%) ÷ (100×38%) = 96.8%。
  • 基于角色的动态数据隔离：从 Session 解析用户角色，教师账号仅可查询本人授课与考核数据，查询层动态注入工号过滤条件，保障数据安全。
  • 通用组件封装：封装统一分页查询组件（PageUtils／MPUtil），支持排序、区间、模糊查询复用，减少重复代码、提升开发效率。
  • 系统测试：用 JMeter 模拟 500 并发用户（学期末考核高峰场景），连续运行 30 天验证稳定性，并完成四款主流浏览器的兼容性验证。

成果

500并发用户
500ms平均响应
80/s稳定吞吐
11核心业务表

压测平均响应 500ms、峰值 800ms，稳定吞吐 80 次/秒；连续运行 30 天无服务中断 （MTBF > 29 天）；Chrome、Firefox、Edge、360 浏览器兼容性验证通过。 系统覆盖用户管理、课程管理、过程化考核、达成度分析四大功能模块， 成果获软件著作权登记（第一著作权人，登记号 2025SR0343232），并通过本科毕业设计答辩。
